# Соглашения для агентов и разработчиков

## Коммиты

Все коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <описание>
```

- **type** — один из: `feat` (новая функциональность), `fix` (исправление бага),
  `chore` (служебные изменения), `docs` (документация), `refactor` (рефакторинг без изменения
  поведения), `test` (тесты), `build` (сборка и зависимости), `ci` (CI/пайплайны), `perf`
  (оптимизация), `style` (форматирование, без изменения логики).
- **scope** — необязательный, если изменение затрагивает только часть проекта. Используется
  `frontend`, `backend` или `spec`; для изменений по всему репозиторию scope опускается.
- **описание** — настоящее время, повелительное наклонение, с маленькой буквы, без точки в конце.
  Ограничение длины — до 72 символов.

Примеры:

```
feat(frontend): add event type selection on booking page
fix(backend): prevent double booking of the same slot
chore: add Makefile with dev/build/test targets
docs: describe commit convention in AGENTS.md
```

Правила для коммитов агента:

- Каждый коммит должен быть атомарным: одна логическая единица работы.
- Агент оформляет свои коммиты по тем же правилам, что и человек.
- Если изменению не подходит ни один существующий type, выбирается наиболее близкий по смыслу;
  сомнительные случаи согласуются с пользователем перед коммитом.
